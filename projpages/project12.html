Apartment Finder

So, I've been a bit of a bum. 1) I start work in one (1) day and didn't find an apartment in Cupertino. 2) I haven't set up OpenClaw, which is also pretty bummy, considering I probably hear about OpenClaw more than the weather (thanks, Stanford). To kill two birds with one stone, I'm going to build out a widget that helps me find short lease apartments in Cupertino, under a certain price (low - if you're curious), and helps me get an apartment!

I'm going to set up the frontend as a Swift app (yay Mac!) which posts to a local HTTP server that acts as a bridge between the frontend and soon... my OpenClaw agent. This will give my frontend a stable API, so I can say, select an area, a max price, a min price, etc. and those values will be sent to my local server. From there, I'm going to have OpenClaw sit behind my server as a reasoning layer--it'll interact with the internet, filter postings, and give me apartments I can afford... hopefully.

Right now, this is the json format that my front end inputs are being posted in. 


        POST /apartments/search payload:
          {
            "state": "California",
            "maxPrice": 3300,
            "minLeaseDays": 90,
            "maxLeaseDays": 110,
            "area": "Cupertino"
          }
Once this json is recieved by the backend, it gets logged and routed to 'live' or 'demo' (have to save those tokens). A JS runner builds a natural-language prompt and launches the agent search. 

      openclaw agent --local --json --session-key agent:apartment-scraper:default --timeout 180 --message ""
OpenClaw then browses the internet and returns json-like output, from which we can extract the relevant information and then normalize to the app's schema. Since the OpenClaw response often comes back wrapped in raw metadata, the runner looks inside fields like 

          payloads[0].text
          finalAssistantVisibleText
          finalAssistantRawText
And then a normalize listings javascript cleans the data, ensuring that the required fields exist, the URLs work, and deduplicates any repeated listings. The server then returns the json to the Swift frontend, giving us a bunch of listings.
